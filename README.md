# أوراد المسلم — Flutter

مشروع Flutter وDart أصلي يعيد بناء التطبيق المرفق، دون WebView أو تشغيل HTML/JavaScript.

## المتطلبات والتشغيل

- Flutter **3.32.8 stable** مع Dart المرفق به.
- JDK **17** وAndroid SDK **35** وأدوات Android command-line؛ الحد الأدنى للجهاز Android 6 / API 23.
- اتصال أولي لحزم pub وGradle ومكونات Android. تحتاج خدمات القرآن والصوت اتصالاً لتنزيل الملفات لأول مرة.

من جذر المشروع:

```bash
flutter doctor -v
flutter pub get
shtool/bootstrap_android.sh
flutter run
```

على Windows استخدم Git Bash لتشغيل `tool/bootstrap_android.sh` مرة واحدة، ثم استخدم Flutter كالمعتاد. ينشئ Flutter ملف `android/local.properties` حسب SDK المحلي؛ لا تنسخه من جهاز آخر.

```bash
flutter analyze --no-fatal-infos
flutter test
flutter build apk --release
```

مكان الملف: `build/app/outputs/flutter-apk/app-release.apk`.

APK الحالي موقّع بمفتاح التطوير لسهولة التثبيت والتجربة. قبل النشر في متجر Google Play أضف مفتاح إصدار خاصاً وإعدادات توقيع آمنة؛ لا تحفظ مفاتيحك في Git. لم يُنشأ APK محلياً أثناء هذه المهمة؛ لم تتوفر أدوات Flutter وتعذّر الوصول إلى الوكيل لتنزيلها.

## الوظائف

- واجهة عربية RTL مع خمسة أقسام، تصميم Material 3، خمسة ألوان ووضع ليلي وحجم نص قابل للتغيير.
- **١٥٠ مجموعة / ٩١٢ بطاقة** من النص الأصلي، تشمل أذكار الصباح والمساء والنوم، الأحزاب، ختم الإخلاص، وأوراد دلائل الخيرات للأيام السبعة.
- العدّ بالتلامس وحفظ المتبقي، إعادة العدّ، إحصاء الأذكار اليومي والإجمالي، مصادر الأذكار، سبعة أنماط بطاقات، ألوان وتمرير تلقائي ومنع إطفاء الشاشة في القارئ.
- إنشاء الأوراد الخاصة وتسميتها وحذفها، وإضافة أذكار شخصية وتعديلها وحذفها داخل الأقسام.
- مصحف نصي أصلي من ٦٠٤ صفحات، قائمة السور والأجزاء، بحث نصي عربي محلي وعبر API، انتقال للصفحات، مفضلة وثلاث علامات قراءة/حفظ/مراجعة.
- تنزيل نص القرآن، مكتبة تسجيلات لعشرة قراء وتنزيل على مستوى الآية والسورة والقارئ مع الإلغاء والاستكمال وحذف الملفات. تشغيل آيات متتابع، تشغيل ملفات الورد الأصلية أو ملف صوتي من الجهاز، مؤقت نوم وسرعة وتكرار وعلامات صوتية.
- استوديو بطاقات: نص عربي، ألوان وخلفية من الصور، إطار وحجم واتجاه، مشاركة PNG وحفظه وطباعة البطاقة أو إخراج PDF. النص يُرسم بواسطة Flutter قبل إضافته إلى PDF للمحافظة على تشكيل العربية واتجاهها.
- تخصيص صورة ونص الإهداء، تصدير/استيراد JSON للإعدادات والأوراد والمفضلة والتقدم، وإدارة الملفات المحفوظة. النسخة الاحتياطية لا تتضمن ملفات الصوت والصور أو ملفات تنزيل القرآن.
- تذكيرات يومية محلية، وخدمة Android أصلية لذكر عائم قابل للسحب فوق التطبيقات وإيقافه من الإشعار. تمنح إذن الظهور فوق التطبيقات من النظام ثم تعيد تفعيل الخيار.
- خطة ختمة موزّعة على الأيام، تسجيل إنجاز الورد وتعديل الموضع، وبطاقة آية اليوم.

## GitHub Actions

الملف `.github/workflows/android.yml` يعمل عند push إلى `main` أو Pull Request أو التشغيل اليدوي من Actions. يثبّت Flutter وJava، يتحقق من Gradle Wrapper بواسطة SHA-256 الرسمي، يجلب الحزم، يشغّل التحليل والاختبارات، ويبني APK ثم يرفعه كـartifact باسم **awrad-almuslim-apk**. التحليل يفشل عند الأخطاء والتحذيرات؛ ملاحظات التنسيق والأسلوب لا توقفه.

لم يُرفع المشروع أو يُشغّل Workflow على GitHub ضمن هذه المهمة. بعد رفع الملفات، افتح **Actions → Flutter Android APK**، ثم نزّل artifact من التشغيل الناجح. لا يُفترض نجاح أول تشغيل قبل فحص نتيجته.

## حالة التحقق والحدود

- نجح `python3tool/validate_content.py`: الأعداد وتفرّد المعرّفات ومجالات مراجع الآيات والتكرار وملفات Android XML.
- نجح فحص صياغة سكربتات shell وفحص الفروق. هذه الفحوص لا تعادل Dart analyzer أو بناء Android.
- **لم تعمل** أوامر Flutter للتحليل والاختبار والبناء لأن Flutter/Dart غير مثبتين، والوكيل الشبكي غير قابل للاتصال. توافق الحزم وبناء Kotlin وتشغيل الميزات على جهاز Android لم يتم التحقق منها عملياً بعد. اختبارات Flutter موجودة لتشغيلها في CI أو جهاز مجهّز.
- لا يوجد `pubspec.lock` مولّد؛ لا نختلق قفل اعتماديات دون حل الحزم. بعد أول `flutter pub get` ناجح، أضف `pubspec.lock` إلى Git لتثبيت إصدارات تطبيقك.
- الملف الثنائي `gradle-wrapper.jar` ليس مضمّناً؛ يجلبه السكربت من مصدر Gradle الرسمي ويتحقق من بصمته، ويُنفّذ ذلك تلقائياً من `gradlew` وعلى CI.
- بعض روابط Google Drive الأصلية قد تنتهي أو تتطلب صلاحية. يعرض التطبيق فشل التحميل، ويتيح ملفاً محلياً؛ لا يدّعي أن هذه الروابط اختُبرت. التنزيل يقبل MP3 ويتحقق من ترويسة الملف.
- يحتوي الأصل نفسه على نص تجريبي لدعاء ليلة النصف من شعبان، ونص تجريبي في مدخل دلائل الخيرات. لم نخترع بدائل دينية؛ مدخل دلائل الخيرات يفتح أوراد الأيام الفعلية. يجب اعتماد نص مرخّص لدعاء ليلة النصف من شعبان قبل إصدار نهائي.
- يدعم المشروع Android. لا توجد مجلدات iOS أو Windows أو web مولّدة أو مختبرة. المنبهات غير دقيقة لتجنّب اشتراط صلاحية التنبيه الدقيق؛ قد يؤخرها توفير البطارية. الذكر العائم يُفعّل بطلب المستخدم ولا يعاد تشغيله تلقائياً بعد إغلاقه.
- مقارنة وظائف المصدر وتفاصيل الاختلافات في `MIGRATION.md`. هذه إعادة بناء أصلية، وليست تطابقاً بصرياً حرفياً مع كل خيار زخرفي في HTML.

## إصلاح تراخيص Android في CI

يُثبّت الإجراء `setup-android` أدوات سطر الأوامر فقط (`packages: ''`). يتولى `tool/setup_android_ci.sh` قبول التراخيص بإجابات تلقائية محدودة، ثم يتحقق من قبولها مع إغلاق stdin، مع حدود زمنية تمنع انتظار إدخال يدوي. تُثبّت فقط `platform-tools` و`platforms;android-35` و`build-tools;35.0.0` و`ndk;26.3.11579264`، دون إضافات Google TV أو محاكيات. إصدار NDK يطابق Flutter 3.32.8، وBuild Tools مثبت صراحة في Gradle. عرض أسماء تراخيص إضافية لا يعني تثبيت إضافاتها.

يمكن فحص منطق السكربت محلياً دون SDK باستخدام `python3 tool/test_android_setup.py`. هذه اختبارات محاكاة لقبول التراخيص وقائمة الحزم وتمرير أخطاء التثبيت، وليست بناء Android فعلياً. يعمل Workflow أيضاً عند الدفع إلى `feat/native-flutter-app`.
